# FaceRoll Recognition Setup on Windows

This guide lists the Windows PowerShell commands needed to install, test, and start FaceRoll facial recognition.

## Current Migration Status

FaceRoll is being migrated to one shared `Facenet512` recognition core for the mobile app and instructor classroom camera.

The shared core currently provides:

- `Facenet512` embedding generation
- Single-face and multiple-face processing
- Cosine-distance verification and identification
- A validated three-sample enrollment schema

The existing Windows classroom adapter has not yet been connected to the shared core. It still uses its previous `Facenet` implementation. The existing mobile Flask backend is also still separate. Do not mix enrollment files generated by `Facenet` with new `Facenet512` enrollment records.

This document must be updated as the remaining migration phases are completed.

## Prerequisites

Install:

- Git
- Python 3.10
- Docker Desktop for Windows using the WSL 2 backend
- Node.js and npm
- Firebase CLI for the local instructor dashboard
- A working webcam

Confirm the required programs in PowerShell:

```powershell
git --version
py -3.10 --version
docker --version
docker info
node --version
npm --version
firebase --version
```

Docker Desktop must be running before starting a classroom-recognition session.

## Repository Location

Open PowerShell and move to the repository root. Replace the example path with the actual clone location:

```powershell
cd C:\Projects\FaceRoll-Group-4-Cowboys
```

## Create the Recognition Environment

Move to the shared recognition directory:

```powershell
cd FaceRoll-System\recognition
```

Create a Python 3.10 virtual environment:

```powershell
py -3.10 -m venv .venv
```

Activate it:

```powershell
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks script activation, allow it for the current terminal only:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

Upgrade the Python installation tools:

```powershell
python -m pip install --upgrade pip setuptools wheel
```

Install the shared recognition package and its tests:

```powershell
python -m pip install -e ".[test]"
```

Install the packages currently required by the Windows classroom adapter:

```powershell
python -m pip install -r windows\requirements.txt
```

## Test the Shared Facenet512 Core

From `FaceRoll-System\recognition`, run:

```powershell
python -m unittest discover -s tests -v
```

The expected result at the end is:

```text
OK
```

Confirm the model contract:

```powershell
python -c "from faceroll_recognition import SETTINGS; print(SETTINGS)"
```

The output must show:

```text
model_name='Facenet512'
detector_backend='opencv'
distance_metric='cosine'
distance_threshold=0.3
embedding_dimension=512
```

The first real embedding operation downloads the `Facenet512` weights. By default, DeepFace stores model weights under:

```text
C:\Users\<WindowsUser>\.deepface\weights
```

Do not commit model weights, enrollment photographs, or embedding files to Git.

## Start the Instructor Dashboard Locally

Open a new PowerShell window and move to the dashboard directory:

```powershell
cd C:\Projects\FaceRoll-Group-4-Cowboys\FaceRoll-System\Instructor-Dashboard
```

Install the Firebase CLI if it is not already available:

```powershell
npm install --global firebase-tools
```

Start the local Firebase services:

```powershell
firebase emulators:start
```

The default local services are:

| Service | Address |
|---|---|
| Instructor dashboard | `http://localhost:5001` |
| Authentication emulator | `http://localhost:9099` |
| Firestore emulator | `http://localhost:8080` |

Keep this PowerShell window running.

## Start the Windows Recognition Bridge

Open another PowerShell window and move to the Windows recognition adapter:

```powershell
cd C:\Projects\FaceRoll-Group-4-Cowboys\FaceRoll-System\recognition\windows
```

Activate the recognition environment created earlier:

```powershell
..\.venv\Scripts\Activate.ps1
```

Start the bridge:

```powershell
python bridge_server.py
```

Expected message:

```text
FaceRoll bridge listening on http://127.0.0.1:8765
```

Keep this PowerShell window running.

## Check the Bridge

From another PowerShell window:

```powershell
Invoke-RestMethod http://127.0.0.1:8765/health
```

The response should report that the bridge is available and show the current capture and recognizer status.

## Start a Classroom Session

1. Confirm Docker Desktop is running.
2. Open `http://localhost:5001` in a browser.
3. Sign in as an instructor.
4. Open the Live Session page.
5. Select a course.
6. Start the session.

The dashboard calls `POST /start-session` on the bridge. The bridge then:

1. Builds the `faceroll-windows` Docker image if it does not exist.
2. Starts the Docker recognition worker.
3. Starts `capture.py` on the Windows host.
4. Captures webcam frames locally.
5. Returns recognition events to the dashboard.

The first Docker build and first model download can take several minutes.

To stop recognition, use the dashboard's session button. To stop the bridge directly, focus its PowerShell window and press `Ctrl+C`.

## Manual Classroom Recognition Test

The dashboard normally controls both processes. For troubleshooting, they can be started separately.

From `FaceRoll-System\recognition\windows`, build the image:

```powershell
docker build -t faceroll-windows .
```

Start the recognizer:

```powershell
docker run --rm -i -e PYTHONUNBUFFERED=1 -v "${PWD}\shared:/app/shared" -v "${PWD}\embeddings:/app/embeddings" -v "$env:USERPROFILE\.deepface:/root/.deepface" --name faceroll-recognizer-windows faceroll-windows
```

In another PowerShell window, activate the environment and start webcam capture:

```powershell
cd C:\Projects\FaceRoll-Group-4-Cowboys\FaceRoll-System\recognition\windows
..\.venv\Scripts\Activate.ps1
python capture.py
```

Press `q` in the webcam window to stop capture.

To stop the manually started recognizer:

```powershell
docker stop faceroll-recognizer-windows
```

## Current Legacy Enrollment Commands

The following scripts currently belong to the older Windows `Facenet` workflow:

```powershell
python enroll_student.py --student-id 12345 --first-name Jane --last-name Doe --images C:\path\to\front.jpg C:\path\to\left.jpg C:\path\to\right.jpg
```

```powershell
python webcam_enroll.py --student-id 12345 --first-name Jane --last-name Doe --samples 3
```

Do not use their output as shared `Facenet512` enrollment data until these adapters have been migrated. `Facenet` and `Facenet512` embeddings are incompatible.

## Current Mobile Recognition API

The mobile application still uses the temporary Flask service under `backend\app.py`. It has not yet been replaced by the shared recognition adapter.

From the repository root:

```powershell
py -3.10 -m venv backend\.venv
.\backend\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r backend\requirements.txt
python backend\app.py
```

The API defaults to port `5001`, which conflicts with the Firebase Hosting emulator. To run it on port `5002` in the current PowerShell session:

```powershell
$env:FACEROLL_PORT = "5002"
python backend\app.py
```

The mobile app's `backendUrl` must use the instructor computer's LAN IP and the same port. This temporary backend will be removed after the mobile app is connected to the shared recognition service.

## Troubleshooting

### Docker is unavailable

```powershell
docker info
```

Start Docker Desktop if this command cannot contact the Docker engine.

### Bridge health check fails

Confirm `bridge_server.py` is still running and that port `8765` is not occupied:

```powershell
Get-NetTCPConnection -LocalPort 8765 -ErrorAction SilentlyContinue
```

### Webcam does not open

- Close applications already using the camera.
- Confirm Windows camera privacy settings permit desktop applications.
- Confirm the correct camera index is configured in `capture.py`.

### TensorFlow reports no CUDA or TensorRT

CPU recognition still works. CUDA and TensorRT messages are informational unless GPU acceleration is explicitly required.

### Model download fails

Check that the Windows user can write to:

```text
C:\Users\<WindowsUser>\.deepface\weights
```

Also confirm that GitHub release downloads are reachable from the computer.

### Recognition reports no enrolled faces

Confirm compatible JSON files exist under:

```text
FaceRoll-System\recognition\windows\embeddings
```

During the current migration, confirm those records were created by the model used by the active adapter. Never mix `Facenet` and `Facenet512` records.

## Shutdown

Stop the classroom session from the dashboard, then press `Ctrl+C` in the bridge and Firebase emulator windows.

Deactivate the Python environment:

```powershell
deactivate
```
